# Metric and control inventory

Audited against the current source and installed macOS 27 SDK on 2026-10-12. “Placeholder” below means an unavailable dash, an empty labelled graph or a disabled control. The app does **not** generate fake usage values. The exact CPU-only memory overlay is also not mocked: it is explicitly a residual estimate.

Two buckets describe the missing features. “Possible” includes work that would need a separately approved privileged helper or hardware-specific research; it does not promise that every Mac exposes a usable counter. “Not possible” means the exact Windows feature has no macOS equivalent, or the requested exact data is not obtainable under this app's ordinary-user, offline, no-helper constraints. It does not mean no Apple-internal tool or future OS could ever provide related information.

## 1. Possible, but not wired up or not available in this build

| Feature currently absent/partial | What would be needed | Current presentation |
| --- | --- | --- |
| Live CPU speed | Apple's `powermetrics` reports frequency on supported hardware, but requires superuser access. Apple silicon has multiple frequency domains; a single GHz number needs a stated aggregation rule. No helper is installed. | Speed is —. |
| Base CPU speed | `hw.cpufrequency` is already queried; it is absent on some Apple silicon machines. A verified per-model specification could be shown as static metadata, never substituted for live speed. | Real value if available, otherwise —. |
| Per-process architecture / Rosetta status | The SDK exposes `proc_pidinfo(PROC_PIDARCHINFO)` and `proc_archinfo.p_cputype`. Query/cache it by PID and creation time; access failures remain nil. | Architecture is —. |
| Process file description / startup publisher | Resolve bundle metadata and validate code-signing identity using Security framework. An unsigned file may have no trustworthy publisher. | Description uses the process name; Publisher is —. |
| Per-process network and observed network history | `powermetrics` has `--show-process-netstats`; it requires an approved privileged collection design. Private networking APIs are another, less stable route. Current public interface counters cannot attribute bytes to a process. | Network columns/history are —. |
| Power usage and power trend | A defined Mac energy-impact score or privileged `powermetrics --show-process-energy`. A Mac score is not the same scale as Windows Power usage. Need measured data, bounded history and permission design. | Power columns are —. |
| Disk average response time | IOKit defines operation counts, total operation times and latency times. Compute validated per-device deltas where the driver supplies coherent values; mounted APFS volume capacity is a separate resource. | Average response time is —. |
| Disk active time | Some drivers may provide busy/idle residency counters. Total read/write times alone can overlap and cannot safely be converted to Windows active-time percentage. Needs driver-specific validation; no universal counter is assumed. | Active-time graph is empty. |
| Physical-device capacity / free space | Physical capacity can be joined to IOMedia metadata. Free space belongs to mounted filesystems/APFS containers, not to a raw throughput device; keep the meanings separate. | Throughput-device Capacity/Available are —; mounted-volume values are real. |
| Network connection type | Classify interfaces using local system configuration metadata instead of presenting the interface display name as a type. | The current Connection type field repeats the adapter display name. |
| More static CPU topology/cache metadata | Existing public sysctl fields are queried already. Performance/efficiency-cluster cache fields could be added with labels that describe shared caches accurately. Missing L3 may mean no L3, not a collector bug. | Supported fields show real metadata; others —. |
| GPU-specific missing utilization/memory/core counters | Current IOKit keys are driver-specific. Additional validated driver keys or a documented future API can extend coverage; no value is inferred from load on another engine. | Available GPU/renderer/tiler/memory values are live; missing values —. |
| GPU Video Decode/Encode, temperature and ANE telemetry | Hardware may expose additional private/privileged counters. Requires hardware-specific research and separate authorization before adding a helper. No portable ordinary-user API has been established for these system-wide metrics. | Video Decode is an empty labelled chart; other absent metrics are not shown as live values. |
| Startup impact | Prospective measurement during startup, with explicit consent and a defined Mac metric. The app cannot reconstruct pre-installation boot timings. | Not measured. |
| System daemon runtime state | Read accessible launchd system-domain job states separately from configured plist values. Permission failures must remain unknown. | Configured/load-state-unknown where not verified. |
| Start/stop/restart launchd jobs | User-domain controls are implementable; system jobs require explicit administrative authorization and safety rules. Inventory intentionally remains read-only. | Controls disabled. |
| Disconnect another user session | Requires an explicitly authorized administrative session-management design; do not signal loginwindow or guess a logout command. | Disabled. |
| Minimize on use / hide when minimized | Implement Mac window behavior intentionally (and provide a reliable restore route). These are product choices, not OS impossibilities. | Disabled Windows-compatible settings. |
| Show full account name | Resolve local account display names and make the preference functional. Usernames currently identify sessions. | Disabled. |

The CPU speed finding is supported by the installed `powermetrics(1)` manual, which documents frequency sampling and process network/energy options. Running the ordinary-user command returned “must be invoked as the superuser.” Apple's [energy-efficiency guide](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/MonitoringEnergyUsage.html) also describes the tool and profiling workflow. Architecture is documented in Apple's [XNU proc_info.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_info.h). Disk times are defined by Apple's [IOBlockStorageDriver header](https://github.com/apple-oss-distributions/IOStorageFamily/blob/main/IOBlockStorageDriver.h), including nanosecond total-time and latency counters; availability is driver-dependent.

## 2. Exact Windows behavior/data is not available on this Mac

| Feature | Why the exact feature is unavailable | Meaningful Mac alternative |
| --- | --- | --- |
| Windows kernel handles, handle count, UAC/elevation and registry/file virtualization fields | Windows object/security concepts do not exist as the same counters on macOS. File descriptors and Mach ports are different resources. | Add separately named descriptor/port/privilege fields where access permits. |
| Windows CPU affinity mask and Efficiency mode | There is no matching arbitrary foreign-process Windows affinity/EcoQoS control exposed by this app's public Mac APIs. Advisory affinity tags are not a CPU pinning mask. | Existing nice priority controls; an explicitly designed Mac background-policy feature. |
| Windows GPU engine numbers/names and dedicated VRAM totals | WDDM engine identities do not exist on Apple silicon; its GPU uses unified memory. | Current renderer/tiler activity and driver-reported shared-memory counters. |
| Exact, disjoint “CPU used memory versus GPU used memory” split | CPU and GPU can reference the same physical allocations. Subtracting counters is not an independently measured CPU allocation total. | Total/system/GPU lines and clearly labelled CPU/other residual estimate. |
| Windows committed/paged/nonpaged pools, hardware-reserved RAM, DIMM slots/speed, and BIOS startup time | These exact Windows memory/firmware layouts do not map to this Apple silicon app. This ordinary-user build has no verified exact hardware-reserved RAM counter. | App/wired/compressed/cache/swap memory and Mac startup metadata where meaningful. |
| Retrospective all-app metered-network/notification history | No public ordinary-user API supplies another app's historical notification counts or Windows metered-network accounting. Data never observed cannot be recovered. | Explicitly opt-in future observed counters where a collection API exists; no invented backfill. |
| Directly toggling every other app's managed Login Item | `SMAppService` manages an app's own services, not arbitrary other applications' user-approved login registrations. | Open Login Items in System Settings; separately manage user-authored launchd jobs if designed and authorized. |

Apple's [SMAppService documentation](https://developer.apple.com/documentation/servicemanagement/smappservice) describes service management for an app and its helper executables. Apple's [Metal memory documentation](https://developer.apple.com/documentation/metal/choosing-a-resource-storage-mode-for-apple-gpus) explains shared/unified memory. These limits are distinct from features simply not implemented yet.

## Real features already connected

Process CPU, footprint memory, threads, identity/start time, executable/user/status and supported disk I/O; total/logical/kernel CPU history and uptime; physical/used/free/wired/compressed/cached/swap memory and pressure; local interface totals/rates/IPv4; mounted-volume capacity and separately labelled physical-device throughput; driver-provided GPU/renderer/tiler utilization and GPU memory; safe process actions; local startup/service/session inventory; opt-in observed CPU/disk history. Missing or denied readings remain unavailable rather than fabricated zeros. Pressure starts Unknown until a real reading/notification arrives.
